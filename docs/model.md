# Математическая модель оптимизации выбора обеда

## Постановка задачи
Необходимо подобрать набор блюд из доступного меню, стоимость которого максимально близка к заданному бюджету пользователя.

## Переменные
Пусть:
- `n` — количество блюд в меню
- `x_i ∈ {0,1}` — бинарная переменная, указывающая, выбрано ли блюдо i
- `p_i` — цена блюда i
- `c_i ∈ {1,2,3,4,5}` — количество порций блюда i
- `B` — бюджет пользователя
- `d` — флаг наличия скидочной карты (0 или 1)
- `h` — час посещения

## Целевая функция
Минимизируем отклонение итоговой стоимости от бюджета:
F(x) = |C(x) - B| → min
где `C(x)` — итоговая стоимость с учётом скидок и наценок:
C(x) = (∑ p_i * c_i) * (1 + s(h)) * (1 - k * d)
где - `s(h)` — коэффициент наценки в час пик:
s(h) = 0.2, если h ∈ {12,13,14,18,19,20}
s(h) = 0, иначе
где - `k` — коэффициент скидки по карте:
k = 0.1, если ∑ p_i * c_i > 500
k = 0, иначе

## Ограничения
1. Минимальный заказ: `∑ c_i ≥ 1` (хотя бы одно блюдо)
2. Максимальное количество блюд: `∑ 1 ≤ 4` (не более 4 различных блюд)
3. Количество порций каждого блюда: `1 ≤ c_i ≤ 5`

## Метод решения
Используется метод полного перебора (brute force) всех комбинаций из 1-4 блюд. 
Сложность алгоритма: O(C(n,1) + C(n,2) + C(n,3) + C(n,4)) = O(n⁴)

При n=10 это 385 комбинаций, что допустимо для консольного приложения.

## Пример расчёта
Меню: Цезарь(150), Борщ(120), Компот(50)
Бюджет: 300 руб.
Карта: нет
Час: 13 (пик, наценка 20%)

Оптимальный набор: Цезарь + Борщ
База: 270
Наценка: 54
Итог: 324
Отклонение: 24 руб.
